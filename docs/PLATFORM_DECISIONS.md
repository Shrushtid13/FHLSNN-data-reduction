# Platform Decision Log

| # | Decision | Reason | Alternatives Rejected |
|---|---|---|---|
| PD1 | Use Python `redis` package with LPUSH / BRPOP instead of RQ or Celery | Windows OS compatibility. RQ and Celery fork worker processes which rely on POSIX `os.fork()`, failing or malfunctioning natively on Windows. FastAPI pushes jobs with `r.lpush("fhlsnn:jobs", json.dumps({"experiment_id": experiment_id}))` and the worker pops jobs with `r.brpop("fhlsnn:jobs", timeout=5)`. | RQ (rejected: Windows fork issues); Celery (rejected: heavy dependency and Windows event-loop instability). |
| PD2 | Two Supabase clients in Express (Anon client per request + Service role client for storage) | Enforces Row Level Security (RLS) on Postgres tables based on user auth tokens. Express constructs an anon client passing the user's Bearer token so RLS policies are evaluated for database rows. The service-role client is used strictly for server-side storage bucket uploads and FastAPI internal communication, keeping the service role key safe from the client. | Single service role client everywhere (rejected: bypasses RLS in Postgres); Browser direct to DB (rejected: bypasses CSV validation and rate limiting). |
| PD3 | Polling via Express (`GET /experiments/:id`) | UI polls Express every 2 seconds until status is `done` or `failed`. Simple, robust, stateless, does not require WebSocket infrastructure or state synchronization. | WebSockets / Server-Sent Events (rejected: unnecessary complexity for low-frequency status transitions). |
| PD4 | Client Bundle Secret Isolation (`envPrefix: ['VITE_']`) | Prevent Vite from bundling server-side secrets (`SUPABASE_SERVICE_ROLE_KEY`) into the browser bundle. Client-safe keys (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`) are explicitly injected via Vite's `define` config. | Exposing `SUPABASE_` prefix (rejected: leaks full database admin keys to client browser). |
| PD5 | Asynchronous Streamed CSV Parsing & Sanitization | Synchronous parsing of 10 MB CSVs blocks the Node.js event loop causing DoS. Async streaming parsing (`csv-parse`) with strict formula injection sanitization (`=`, `+`, `-`, `@`) ensures responsiveness and client safety. | Synchronous `split('\n')` parsing (rejected: event loop starvation and DoS vulnerability). |
| PD6 | Constant-Time Internal Token Comparison | Use `secrets.compare_digest` in FastAPI and constant-time string check for inter-service communication (`X-Internal-Token`) to prevent timing side-channel attacks. | Standard equality `==` check (rejected: susceptible to statistical timing attacks). |
| PD7 | Defense-in-Depth Authentication on All Endpoints | All API routes (including stubs returning 501) require valid Supabase user JWT authentication, and internal ML endpoints require `X-Internal-Token`. All DB errors and tracebacks are sanitized before returning HTTP responses. | Unauthenticated stubs or open internal job inspection (rejected: exposes system internals and bypasses ownership checks). |
